# 设计理念

[设计规范](design-principles.md) 定义具体的几何、材质与动效规则；[应用接入规范](application-integration.md) 列出面向业务工程的接入清单。本文阐述这些规则背后的工程取舍。

规范无法穷举所有边界场景。遇到规范未覆盖的情况时，可从本文的八条理念推导方案；推导结果若与规范冲突，以规范及其 [优先级](design-principles.md#优先级规则冲突时听谁的) 为准，并将遗漏的结论补充进规范。

每条理念都列出库内实现方式、常见反例与自检问题。理解这些取舍后，多数规则无需逐条查阅即可推知。

## 核心主张

> 界面应当像可信的物理实体一样运作：触碰立即响应，运动连续可逆，元素从何处展开便归位何处；底层交互细节由组件库统一承担，应用代码只描述业务逻辑。

Mochi 以 Material 3 Expressive 的配色、字阶与动效令牌为基底，交互手感与物理动态参考 iOS 26，几何轮廓采用 Kyant 的 G2 连续曲率圆角，工程与 API 规范参考 miuix。多方来源发生冲突时的取舍原则见下文各节。

## 1. 连续：同一个物体的持续演变

状态变化表现为同一个元素在空间与形态上的平滑过渡，避免静态画面之间的瞬切。

- 内容原位过渡：
  - 文字替换使用 `MochiBlurText`。
  - 图标切换使用 `MochiMorphIcon`。
  - 出现与消失使用 `MochiBlurVisibility`。
  - 数值变化使用 `MochiCounterText`。
  - 卡片高度变化使用 `mochiAnimateHeight`。
- 从哪来回哪去：菜单从触发按钮中长出并沿原路径缩回；页面从来源卡片（`mochiNavSource`）展开至全屏，返回时缩回原卡片。
- 全程可打断：空间进度直接由弹簧驱动。中途反向或再次点击时，直接继承当前位置与速度继续运动，不跳回起点。
- 先排版、再动画：新内容进入组合后，先完成测量、布局、首帧绘制并等待帧率稳定，再启动进场动画（库内的页面、底部面板、对话框与标签页切换都内置了这一机制）。若排版耗时与动画首帧挤在同一帧，画面就会从起点直接跳到中途。
- 遮挡关系连续过渡：位于浮动栏下方的卡片展开为页面时，浮动栏随展开进度平滑淡出至容器后方（`mochiNavOccluder`），避免出发瞬间被容器生硬遮盖。

**反例**：
- 直接用 `if (loading) Spinner() else Content()` 切换界面。
- 修改目标值后直接调用 `snapTo`。
- 关闭时从头重播一段反向动画。
- 原地直接替换数字文本。

**自检**：当前帧与上一帧之间，是否有任何像素凭空出现或消失？

## 2. 跟手第一：手指移动时界面零帧滞后

手指是用户与界面的唯一物理连接，跟手响应高于一切过渡动画，位列全局优先级第一条。

- 拖动全程 1:1 跟手，松手瞬间将手势速度直接注入后续弹簧动画。
- 拖动过程中逐帧变化的读数直接显示，不叠加计数器动画；仅在松手后由程序修改数值时启用滚动过渡。
- 滚动优先于按压：列表与滚动容器内的按压反馈短暂延迟，一旦滚动接管便立即撤回（`awaitMochiPress`）。
- 越界回弹采用橡皮筋阻尼（`ProvideMochiOverscroll`、`MochiScrollDefaults.flingBehavior()`），避免生硬截停。
- 系统关闭动画时，自动停用所有弹性效果，完整保留业务功能。

**反例**：
- 手指拖动期间仍在播放上一段残余动画。
- 为追求视觉柔化让滑块滞后于手指。
- 松手后先停顿一拍再启动回弹。

**自检**：手指停下的同一帧，界面是否同步停稳？

## 3. 几何先于感觉：先建立数学对齐，再做光学微调

耐看的秩序来自可推导的几何关系，不靠逐处试凑经验数值。

- G2 连续曲率圆角：统一使用 `MochiRoundedRectangle` 与 `MochiCapsule`，圆角半径从 `MochiTheme.shapes` 读取，不使用 `RoundedCornerShape`。
- 同心内缩：圆角容器内贴着内边距放置的圆角元素，内圆角等于外圆角减去内边距（`MochiConcentric`）。
- 四周等距：胶囊容器内的图标到外侧端点的距离，等于到上下边缘的距离。
- 光学平衡约束在几何框架内：图标按字形实际墨迹居中，文字按行框中心对称；光学调整仅作微调，不推翻同心几何。
- 布局消化留白，禁止缩放内容：内容超出单行时自然换行增高，不缩小字号，也不按固定高度硬裁切。

**反例**：
- 为了让单行视觉居中单独添加 `offset(y = 2.dp)`。
- 根据卡片高度或行数反算整体缩放比例。
- 硬编码 `RoundedCornerShape(12.dp)`。

**自检**：这个尺寸能否由外层几何关系推导得出？若无法推导，是否应当定义为语义令牌？

## 4. 实体与克制：画布扎实，材质分明

页面背景与内容卡片始终使用实色分组表面（`groupedBackground` 与 `groupedContainer`），正文内容不包裹装饰性玻璃或彩色渐变。浮在内容之上的栏、菜单、底部面板、对话框与栏内控件支持通过 `MochiTheme(materials = …)` 开启可选的 AGSL 液态玻璃（`MochiGlass`）以及默认开启的滚动边缘模糊（`MochiScrollEdge`）。

- 颜色统一取自 `MochiTheme.colorScheme` 与 `MochiDefaults`，同时适配浅色与深色模式，组件内不硬编码颜色。
- 材质边界清晰：`MochiMaterials` 仅作用于浮动栏与浮层，列表与正文容器始终保持实色；正文按钮默认采用纯色样式（`Filled`、`Tonal`），仅在显式指定玻璃样式（`MochiButtonStyle.ProminentGlass` / `Glass`）且主题开启控件玻璃时绘制液态玻璃。
- 渐变仅用于「实色渐隐至透明」的功能边缘（滚动边缘效果、渐变遮罩），统一采用 S 曲线插值的 `MochiSmoothGradient`，不作背景装饰。
- 按压反馈表现为指尖亮起的柔光与轻微跟手形变（`mochiPressGlow`、`mochiPressDeform`），不描亮边，不产生过曝白斑。
- 触感反馈少而精确，仅在状态实际改变或越过触发阈值时震动。

**反例**：
- 给正文卡片叠加彩色渐变或装饰性背景模糊。
- 用半透明纯色充当按钮底色。
- 每次普通点击都触发震动。

**自检**：去掉这层视觉装饰后，层级或信息是否受损？未受损则去掉。

## 5. 一处实现，处处复用：交互细节由组件库统一承担

同一种交互在组件库中只维护唯一实现。完整复用组件即可继承全部手感与边界处理；自行拼装外形则会丢失过半细节。

- 直接复用完整组件，不拆解重绘局部外壳：
  - 下拉菜单与上下文菜单使用 `MochiDropdown` / `MochiContextMenu`。
  - 按钮使用 `MochiButton` / `MochiBarIconButton`。
  - 设置与键值行使用 `MochiListSection` / `MochiListRow`。
- 通用视觉与手势能力集中在 `effect/` 模块（高光、形变、液态玻璃、融球、内容变换、遮罩），组件与应用统一从该层调用。
- 单一属性单一动画归属：高度、位移等几何属性在同一时刻只由一套动画驱动，外层容器不追赶内层的动画中间值，也不叠加第二层平滑。
- 从根源治理偏差：遇到视觉或对齐偏差时，直接修正库层令牌或组件并沉淀进规范，不在单个业务页面里手填内边距绕过问题。

**反例**：
- 用「普通按钮 + 自绘弹出层」拼装菜单。
- 在单个演示页里给某张卡片额外补内边距掩盖圆角对齐问题。
- 在自带尺寸过渡的内容外再套一层 `animateContentSize`。

**自检**：其他页面遇到相同需求时，能否直接复用这次编写的组件？

## 6. 视觉效果按档降级，业务功能完整保留

在不同 Android 版本与不同性能档位的设备上，手势响应、动画节奏与交互结果保持一致；低档位仅简化高开销渲染效果（液态玻璃、融球、柔和阴影、HDR 高光）。

- 按图形档位与 API 版本降级渲染效果，保持功能一致（见 [兼容性](compatibility.md)）。
- 转场过程仅修改图层属性（`graphicsLayer`），避免逐帧触发重新测量与布局。
- 离屏缓冲仅在需要遮罩或合成时开启，且范围严格限制在最小必需区域。
- 离屏合成置于几何形变外层，防止果冻或橡皮筋形变移出原矩形时被裁出直边。
- 网络请求与大图解码等重负载移出组合与测量阶段，待 `rememberMochiNavSettled()` 转场落定后再执行，加载期间使用 `MochiSkeleton` 占位。

**反例**：
- 在低版本系统上直接隐藏某项业务功能。
- 每帧开启全屏范围的 `saveLayer`。
- 在 `remember {}` 或测量阶段同步解码大图。

**自检**：在性能最低的目标设备上，这套交互链路是否依然完整可用？

## 7. 真实场景验证：面向业务表达，精简调试旋钮

组件的设计质量由真实业务场景检验，不靠满屏参数滑块堆砌。

- 演示页面：
  - 构建真实业务语境（锁屏通知、控制中心、收件箱、相簿）。
  - 保持完整可交互状态。
  - 仅保留一两个最影响手感的关键开关或参数。
- 应用接入：按实际业务场景选用组件；无对应场景的条目注明「不适用 + 原因」，不为凑齐组件凭空添加无关功能。
- 默认值即推荐方案：`XxxDefaults` 已内置调校完毕的默认参数，业务方仅在特定领域需求下覆盖。

**反例**：
- 演示页摆满刚度、阻尼、偏移滑块，却没有任何真实业务内容。
- 为了展示标签栏组件硬塞入与业务无关的空标签页。

**自检**：遮住说明文字后，用户能否一眼认出当前页面所处的业务场景？

## 8. 规范持续演进：发现、根治、沉淀成文

每一次问题排查都需要回答「如何从机制上避免同类偏差再次出现」。

- 在组件库层根治问题；涉及公开行为变更时，同步更新中英文文档与示例工程。
- 将提炼出的新规则写入 [设计规范](design-principles.md)，明确其所属的优先级顺位。
- 验证结果分项陈述：代码格式与编译、自动化测试、实机视觉与交互验收各自独立汇报，不将编译通过等同于交互验收通过。

## 冲突时的裁决顺序

多条理念发生冲突时，按 [设计规范的优先级](design-principles.md#优先级规则冲突时听谁的) 裁决：

**跟手与可用性 > 零裁切与零过曝 > 几何关系 > 光学平衡 > 内容不瞬切 > iOS 细节还原 > 性能与兼容降级。**

典型取舍：
- 拖动滑块时旁侧读数逐帧直出（跟手 > 内容不瞬切）。
- 大面积 HDR 柔光仅轻微提亮，高倍亮度集中于贴边细线（零过曝 > iOS 细节还原）。

## 编码时的决策顺序

1. 明确任务边界：区分「使用库开发应用」与「修改组件库」，两套验收清单互不混用。
2. 优先查找现成组件：确认库内是否已有对应组件或 `effect/` 修饰符，直接完整复用，不拆出一半自行重绘。
3. 读取语义令牌：颜色、字阶、圆角、材质、间距与动效统一从 `MochiTheme` 或 `XxxDefaults` 获取。
4. 检查连续性：为所有动态内容指定过渡组件（理念 1）；确认每段动画可中途打断、继承当前速度，且每个属性只有一个动画归属者。
5. 检查跟手性：确认拖动手势全程 1:1 跟随，松手瞬间将速度传递给弹簧。
6. 检查几何关系：确认内外圆角同心、胶囊端距相等、大字号与换行自然增高无裁切。
7. 检查遮挡与图层顺序：确认浮动栏已挂接 `mochiNavOccluder()`，离屏合成位于形变图层外侧。
8. 分项汇报验证：分别说明编译检查、自动化测试与实机验收的覆盖情况。

## 常见反模式速查

| 反模式 | 违背理念 | 推荐做法 |
|---|---|---|
| `if (a) A() else B()` 直接切换组件 | 连续 | `MochiBlurCrossfade` / `MochiBlurVisibility` |
| `Text(count.toString())` 原地替换数字 | 连续 | `MochiCounterText` |
| `RoundedCornerShape(n.dp)` | 几何 | `MochiTheme.shapes.*` / `MochiRoundedRectangle` |
| 硬编码 `Color(0xFF…)` | 实体与克制 | `MochiTheme.colorScheme` / `MochiDefaults` |
| 给正文卡片加装饰性渐变或玻璃 | 实体与克制 | 使用 `groupedBackground` / `groupedContainer` 实色表面 |
| `clickable` 搭配系统默认水波纹 | 实体与克制 | `mochiPressDeform` + `mochiPressGlow`，设 `indication = null` |
| 普通按钮搭配自绘弹出层 | 复用 | `MochiDropdown` / `MochiPopoverButton` |
| 通用卡片内手写裸 `Row` 充当设置项 | 复用 | `MochiListSection` / `MochiListRow` |
| 在自动画尺寸的内容外再套 `animateContentSize` | 单一动画归属 | 仅保留单一尺寸动画 |
| 在单个页面手凑内边距掩盖对齐偏差 | 根源治理 | 修正库层令牌或组件，并写入规范 |
| 内容尚未完成排版便启动进场动画 | 先排版再动画 | 使用库内置转场，或等待帧率稳定后再启动 |
| 自定义浮动栏未登记遮挡关系 | 连续遮挡 | 在浮动栏最外层添加 `mochiNavOccluder()` |
| 仅由调参滑块构成的演示页 | 真实场景 | 构建真实业务场景，仅保留一两个核心参数 |

## 代码对照

```kotlin
// ✗ 反例：硬编码颜色与圆弧圆角、系统默认水波纹、文字瞬切
Box(
    Modifier
        .background(Color(0xFFEFEFEF), RoundedCornerShape(16.dp))
        .clickable { on = !on },
) { Text(if (on) "已开启" else "已关闭") }

// ✓ 正例：主题令牌与 G2 连续圆角、按压形变 + 指尖高光、文字模糊过渡
val shape = MochiTheme.shapes.extraLarge
Box(
    Modifier
        .mochiPressDeform()
        .background(MochiDefaults.groupedContainer(), shape)
        .mochiPressGlow(rememberMochiGlowState(), shape)
        .clickable(
            interactionSource = remember { MutableInteractionSource() },
            indication = null,
        ) { on = !on },
) { MochiBlurText(if (on) "已开启" else "已关闭") }
```
