# 设计规范

Mochi 的所有组件和示例都遵守这一篇。规则背后的「为什么」见 [设计理念](philosophy.md)，规则没写到的情况从那里推。这里只列规则和取舍，细节、API 和数值在各篇链接里。提交前对照「检查清单」过一遍。

使用本库开发应用时，先按 [应用接入规范](application-integration.md) 逐项接入；修改组件库再读贡献指南。适用侧推页必须使用已登记的共享顶栏控件，来源容器转场则让整页一起变形；规则按业务场景生效，不凭空增加功能。

## 定位

| 方面 | 来源 | 说明 |
|---|---|---|
| 配色、字阶、动效 token | Material 3 Expressive | tonal 配色、跟随系统取色，深浅色都要成立 |
| 形状 | Kyant G2 连续圆角 | Kyant0/Capsule 默认的曲率连续圆角，拉满过渡成胶囊 |
| 交互和动态 | iOS 26 | 从按钮里长出来、按住滑选、橡皮筋、按压从指尖发光、内容原位变换 |
| 材质 | 实体 | **不做玻璃**（不折射、不模糊背景）；iOS 分组样式：灰底白卡片 |
| 工程 | miuix | 参数顺序、`XxxDefaults`、显式 API、中英文文档 |

默认配色与字阶来自 MD3E；可选 [Nothing 外观](nothing-theme.md) 通过相同的语义令牌替换配色、字体和图标，尺寸、同心布局与交互规范继续适用。中文标题使用清晰字体，不使用点阵。

## 优先级：规则冲突时听谁的

从上到下，越靠前越优先：

1. **跟手和可用性**：手指在动时界面必须一帧不差地跟着手指，不能为了过渡效果拖尾巴。系统关了动画就关掉弹性效果。字号跟随系统设置，可点区域不小于 44dp。
2. **不出错、不过曝、不裁切**：内容不能被裁掉、不能盖住相邻内容，HDR 光每个通道不能超过峰值。宁可暗一点、小一点，也不能发白或穿帮。
3. **几何规范**：连续圆角，同心，四周边距相等。
4. **光学平衡**：图标和文字按视觉重心对齐。它只在几何规范之内微调，不推翻同心。
5. **内容不瞬切**：任何内容变化都要有过渡。和第 1 条冲突时听第 1 条，拖动中逐帧变化的读数直接显示。
6. **还原 iOS 的细节**：能还原的尽量还原，还原不了的在文档里写出来；和 MD3E 的配色、字阶冲突时，用 MD3E 的。
7. **性能和兼容**：效果按系统版本降级，**功能不降级**。低版本少了融球和阴影，但手势、动画和结果都一样。

> 例：滑块拖动时旁边的数字直接跳（1 > 5）；松手后程序改值时才用计数器滚动（5）。
> 例：HDR 边缘流光的大面积提亮会刺眼，所以柔光只轻微提亮、贴边细线使用 HDR（2 > 6）。
> 例：列表首末行很矮时，由卡片补足文字安全留白或图标轮廓的同心间距，不让内容挤进圆角。

## 一、形状

- 所有圆角都用 `MochiRoundedRectangle` / `MochiCapsule`（`MochiContinuity`），不用 `RoundedCornerShape`。真正的圆可以用 `CircleShape`。
- 半径从 `MochiTheme.shapes` 取。卡片和面板的圆角是 28dp（`extraLarge`）。
- 像 app 图标那样的方块用超椭圆 `MochiSuperellipse`（默认 n = 5），整条边都在弯，没有接缝。
- 例外：贴着屏幕物理圆角的形状（底部面板后面缩小的页面、页面转场）用屏幕给的圆弧半径，和硬件重合。

详见 [主题 → MochiShapes](theme.md#mochishapes)。

## 二、同心与光学平衡

分组行在宽松圆角参考高度上仅减小 4dp（普通 34dp 图标行约从 66dp 降至 62dp），保留等高、整行居中、主题尺寸与原有水平边距参考；真实内容和上下最小留白仍是下限。

同样式选项的完整行高必须相等：标准行在测量时统一包含圆角安全留白，不再仅给首末项叠加卡片补白。内容中心、点击区域和分隔线共用完整行高，不缩放内容、不硬裁固定高度。


每个选项按**完整可见区域**上下对称，首末项包含卡片补白。标题和副标题作为一个内容块居中，行首图标、文字块、所有行尾插槽共用同一个整体摆放偏移；数值基线、自然尺寸和横向边距保持不变，不能单独移动行尾。卡片先读取自然测量锚点，再在同一轮摆放阶段对齐完整区域的中心；不能把补白后的偏移反馈到测量或缩放。


列表留白通过布局计算，不通过缩放内容消除。禁止从首末留白或卡片行数自动推导整组放大比例，文字、图标、控件遵守主题尺寸；保留安全留白与行内对齐。


1. **同形同心**：圆角容器里贴着内边距放的圆角元素，圆角 = 容器圆角 − 内边距（`MochiConcentric`）。例：列表行首图标块 12dp = 28 − 16；标签栏选中块。
2. **文字光学留白**：纯文字行左右采用稳定的 **22dp**（`MochiListDefaults.TextRowPadding`）；首末留白读取实际排版首行、末行的行框中心，包含字体回退与上下伸空间。文字不等同于固定 12dp 高的胶囊，不用 `H` 或单词墨迹代表所有语言。相同字体、字号和行数保持稳定，换行自然增高。分组小标题和说明也从 22dp 开始。
3. **图标按墨迹居中**：`›`、返回箭头、放大镜都按字形实际墨迹居中，不按包围盒。
4. **靠边的东西不戳进圆角**：要么往里推，要么把它自己的圆角改成同心的。
5. **四周等距**：胶囊里的图标离左端的距离 = 离上下边的距离。
6. **状态排版**：只有未读小点留在标题旁的 `MochiListRow.titleTrailing`。置顶、标记等具名状态统一用 `MochiListStatusChip`，默认放在 `status` 插槽的右下角，与副标题底部对齐；无副标题时在标题下独占一行。日期保留在标题行最右侧。未读小点保留紧凑占位，chip 使用共享内容变换平滑显隐。
7. **左右滑操作胶囊**：操作按钮统一用 `MochiCapsule`，作为操作胶囊保留完整圆头。完整展开后，上、下与外侧边界距离均为 8dp，按钮间距也为 8dp；边界包含卡片首末行补白，高行和大字号同样对齐。卡片先确定补白，按钮在同一轮布局中按完整边界测量、放置；前景底色、按压约束和删除裁切共用该边界。初露出从小圆点长成胶囊，拉满和收起共用同一套几何。按压、跟手、阈值鼓起合并后约束四边，不能靠外层裁掉越界部分。

详见 [主题 → 同心与光学平衡](theme.md#同心与光学平衡)、[列表](../components/list.md)。

行首与行尾独立按各自形状测量，开关、箭头不继承左侧的统一 padding。有行首图标块时，首末边缘读取独立的图标轮廓锚点；没有图标块才按实际排版首末行的行框中心决定文字光学留白，不能把二者混合取最外侧。不使用整行高度的一半代替文字锚点，不给真实文字锚点硬限 8dp。右侧文字与标题共享实际基线。箭头、对勾、加载图标属于整行，墨迹中心按整行居中，有副标题时也不能跟着标题偏上；开关、分段选择器和步进器在所有行保持行内居中；步进器数字与按钮共用中心，禁止为贴圆角上下移动子项或整块行尾。圆角轮廓用于最小安全内缩，整组共用结束边距，首末不足的留白由卡片外壳增加；不能以同心为由破坏横向中线。字体 cap-height 只决定符号尺寸，不决定竖向位置。行尾横向留白按末端元素自身几何计算。首末同心留白由卡片外壳承担，不能通过移动行尾整块内容破坏行内对齐；分隔线结束缩进固定，不随行尾类型改变。

双行标题与副标题/状态使用 `MochiListDefaults.SupportingTextGap`（默认 0dp），先用 `Trim.Both` 去掉每个文字块外侧的行高留白；字号与副标题内部行高仍来自主题。行内上下最小留白统一为 `RowVerticalPadding`（10dp）。普通双行图标横向保留 16dp 同心边距，竖向按完整选项区域居中，大字号、换行或高控件按内容自然增高，不通过负间距、缩字或裁切硬塞进固定高度。

设置项不走“通用卡片 + 裸 Row + 固定 padding”的独立布局：应用使用 `MochiListSection` / `MochiListRow`，演示设置分组使用复用它们的 `DemoSettingsSection`。单行与多行遵守同一首末行留白规则，禁止单行为了压到 52dp 省略同心留白。

演示页介绍卡片使用独立的 24dp 内容内边距与主题 32dp 外圆角，目录入口和详情介绍卡片的图标背景共用同一个 `MochiSuperellipse(5f)`，保持轮廓一致；卡片只保留图标、标题和简介，共用这一内容边界，不再显示「用到：…」。不能通过修改设置行或演示舞台的共享 padding 来扩大介绍卡片留白。 演示首页目录标签的副标题统一为「共 X 个」，按条目总数计数，展开标题和折叠顶栏复用同一个计数；主题页不显示副标题。

## 三、颜色和材质

- 颜色只从 `MochiTheme.colorScheme` 和 `MochiDefaults`（`groupedBackground` / `groupedContainer` / `fill` / `scrim`）取，组件里不写死颜色。示例里的照片、app 图标这类「内容」可以用固定色。
- 分组样式：页面底是 `groupedBackground`，卡片是 `groupedContainer`。浅色下灰底白卡片，深色下最深的底、卡片亮一档。
- 控件底槽（关着的开关、滑块没走到的那段）用半透明的 `fill`，在卡片和底色上都看得清。
- 禁用统一用 `MochiDefaults.DisabledAlpha`（0.4）。
- 阴影要柔、宽、分层，没有断层和色带。
- 主题配色变化（换种子色、取色算法、明暗）也不瞬切：由 `MochiTheme` 整套插值过渡，组件不要自己再给颜色加动画。服从「内容不瞬切」。
- 「贵」的效果（模糊、AGSL、柔和阴影、刷新率）一律按 `MochiGraphics` 图形档位开关，不直接比系统版本；最低一档也要功能完整，只是画法简化。
- 换整套风格用 `crossfade` 原位模糊转场；换明暗用 `MochiThemeRevealHost` 从手指处揭开，深浅没变就直接改、不硬上动画；连续参数（种子色、取色算法）用配色插值，不揭开。两者不叠加：揭开期间配色一步到位。
- 头像统一用框式：可点的 `MochiAvatarButton`，不可点的 `MochiFramedAvatar`，头像和外框同心、四周留一圈缝，不自己画圈。

## 四、文字

- **按分组小标题决定独立大标题**：正文已有「配色」「主题色板」这类卡片外分组小标题时，默认用 `MochiCompactTitleScaffold`（已有滚动容器用 `MochiTitleBar`），仅保留紧凑顶栏，移除正文独立大标题及空占位，分组小标题本身保留。没有这类小标题时可以保留大标题，不能误用说明文字或卡片有无作为判断条件；卡片内部介绍标题不受此规则影响。示例「主题」仅紧凑顶栏；「组件 / 效果 / 导航」初始展开、上滑折叠，返回顶部重新展开，独立保存滚动位置。详见[标题规范](../components/navbar.md#默认标题规则)。

- 字号只用 `MochiTheme.textStyles`，包括 iOS 位置的 `largeTitle` / `navTitle` / `footnote`。
- 行高按居中分配，中文不偏下，和旁边的图标中心在一条线上。
- 文字默认用 `TextMotion.Animated`（亚像素定位）：缩放、移动、改字号时不逐字抖动。
- 长标题先缩字号（`minFontScale`）再省略。
- 大号粗体左边用 `mochiOpticalLeading` 去掉字形自带的空白。

详见 [主题](theme.md)。

## 五、动态

- 弹簧为主：位置和尺寸用 `MochiTheme.motionScheme`，内容变换用 `MochiSprings.snappy(300)`，菜单用 `MochiMotions`。展开可以带一点回弹，收起不回弹。
- **从哪来回哪去**：菜单从按钮里长出来、原路缩回；页面从卡片打开、返回时缩回卡片。
- 被打断时从当前状态接着走，不跳回起点。
- 活动中的按钮被取消或禁用时，必须释放按压形变和高光，并取消连发任务；声明按下/松手事件的归属但不抢父级拖动，不能让禁用按钮持续粘连。悬浮面板在请求打开时及时隐藏导航小白条，不等待弹簧停稳。
- 多页面板使用独立导航器，同时传给 `MochiSheet` 与内部 `MochiNavHost`；顶栏按钮复用 `navId` 参与侧推共享，静止时由外壳统一裁切，内页侧推默认继承面板当前圆角，全屏时底部两角保持直角。返回先退内部页，最后一个子页退出动画中重复返回也不得误关面板或传给后面的页面。
- 提示整条的出现/消失和内部内容替换分别处理：优化进出场时保留文字模糊替换；图标切换、增加和移除同样使用共享内容变换。先测量新旧内容，内外容器共用同一帧的占位尺寸，禁止外层再追赶内层的动画中间值。
- 面板顶栏恢复同心布局：44dp 控件离上/左右边均为 `max(12dp, 顶部圆角 - 22dp)`，不额外增加下边距。顶部沿用 `max(物理圆角, 32dp) - 悬浮边距`，只限制固定上限 48dp（参考真机的 58dp 减 10dp），禁止每台手机都减 10dp。在展开动画完成处直接开启补底，上拉及弹簧回程保留，向下收起、关闭或预测性返回才撤回。后页内容必须完整，不能为藏底边而裁掉下半屏；半屏起点匹配物理屏幕圆弧，半径和曲线控制点随进度连续过渡，到全屏才与前景顶部连续圆角一致。不另加系统高度投影。安全区只作用于内容；选项卡片统一使用共享分组容器色（浅色白卡片）。
- **并排控件同高**：同一行里并排的输入框、按钮、图标按钮共用一个高度 token，不各写各的数字。`MochiTextFieldDefaults.Height` 直接取 `MochiButtonDefaults.Height`（48dp，也是 `MochiIconButton` 默认尺寸），所以输入框旁边的按钮用默认尺寸即可同高、同一条中线；新增并排控件时也从这些 token 取值。容器里面的按钮按同心关系从外层高度推出（输入框里的发送键 = `TrailingButtonSize` = 高度 − 2 × `TrailingInset`），不另写尺寸。
- **出现 / 消失按场景选动画**：会把旁边内容推开的元素用 `MochiBlurVisibility`（占位从 0 长出来）；固定位置上的小按钮（输入框的清除按钮）占位一直保留，只在原地模糊渐显，不能让占位增长带着它从角落滑进来。
- **连续圆角描边用 `Modifier.mochiBorder`**：Compose 的 `border` 遇到任意路径轮廓时用 clipPath 挖空，Android 上没有抗锯齿，圆角处会出锯齿；`mochiBorder` 按缩进半个线宽的同形轮廓直接画描边。圆形、普通圆角矩形可以继续用 `border`。
- **嵌套的整页手势：接手的那一下就消费触摸**：整页右划返回、侧边栏这类都只接「子元素没消费的拖动」，判断阈值一样；里层接手时不消费当前事件，外层会在同一个事件里一起接手（一次右划同时返回又打开侧边栏）。另外按下事件会在 Main 阶段再送一次，行的点按检测已经消费了它，判断「子元素接手了没」只看之后的移动。
- **容器手势不抢内容的拖动**：面板、弹出层这类外层手势在自己真正接手（越过阈值开始滚动）之前不消费移动事件；发现内容已经消费了这次拖动，就整次放手（不发光、不滚、不点选）。滚筒、滑块这类控件要越过触摸阈值才接手，期间的移动只要被外层消费，它就会以为别人接手而放弃，结果划不动。
- **前景一开始离开就放开触摸**：面板、对话框、弹出层、菜单、提示、侧边栏、左滑行开始关闭的那一刻，新的按下就落到下面的页面上，不等关闭动画走完；只有已经按在前景上的那一下（比如正拖着面板往下甩）照常走完。浮层统一在 `InWindowOverlay(leaving = …)` 里判断，新增浮层把「已经在关」传进去即可。
- **所有卡片容器的高度变化默认平滑过渡**：内容、加载状态、行数或展开状态变化时，统一使用 `Modifier.mochiAnimateHeight`，让背景、圆角轮廓和实际占位高度同步变化，下方内容也平滑移动。首次布局直接使用测量高度；后续目标从当前高度继续过渡。宽度即时更新，不拉伸文字。公共卡片、示例卡片和新增自定义卡片都遵守此规则。
- 面板内侧推的轮廓、压暗和阴影共用当前可见表面高度，包含全屏导航区；半屏底部圆角必须位于可见底边，全屏底部保持直角。正文固定测量与安全区不能截短转场图层。
- 手势或已有逐帧高度动画（面板拖拽、左滑删除、页面形变）直接拥有高度，不再叠加第二层平滑。只有这些明确的动画拥有者才关闭卡片的 `animateHeight` 或修饰符的 `enabled`。系统动画倍率为零时立即完成过渡。
- 删除行时，首末行留白与行高一起连续归零，包含多行变单行；不得在回调移除行时才突然释放残余空隙。
- 形变表面的圆角裁切、底色、阴影和内容应一起变换；不要用静止的外层轮廓裁切正在放大或跟手偏移的内层（如提示）。
- **离屏图层不能藏在形变里面**：离屏合成（渐变遮罩的 `CompositingStrategy.Offscreen`）按图层自己的矩形裁切。跟随形变的平移、放大要放在它外层，让离屏图层整体跟着动；离屏只在真的有东西要擦时才开（`mochiFadeMask` 不遮时自动关掉）。否则内容一跟着果冻、橡皮筋移出原来的矩形，就被一个看不见的方框切出直边。
- **铺满卡片的内容裁进卡片形状**：内容没有内边距、贴着卡片四边时（演示舞台、自带底色的预览），由卡片统一裁进自己的圆角形状，不能让内容的矩形底色把圆角盖成直角。
- 越界用橡皮筋（iOS 回弹公式），不硬停。
- 系统关了动画时弹性效果全关，内容变换瞬间完成。
- **滚筒：每格一震、停稳才回调、外部改值也滚过去**：滚筒类控件（[`MochiWheelPicker`](../components/picker.md) 及其组合）每滚过一格轻震一下；松手后先惯性滚动再临界阻尼吸附，不回弹；只在停稳后回调选中值；外部改了选中项要用动画滚到位，不能瞬跳。循环滚筒走近路。
- **不合法的值先显示、再滚回**：日期滚筒滚到这个月没有的日子（2 月 30 日）时，不禁止滚到，也不瞬间改值：先变灰，停稳后再由回调把值改回合法项，滚筒自己滚回去。其他「范围约束」类滚筒同理。
- **按钮弹出的东西都走菜单引擎**：菜单、弹出层、从按钮弹出的操作确认、表单行尾的紧凑日期 / 菜单式选择，触发者都是按钮，统一用 `MochiDropdown` / `MochiIconDropdown` / `MochiPopoverButton` / `MochiConfirmationDialogBox`（内部都是同一个 `DropdownCore`）。不要「普通按钮 + 另画一个浮层」：那样按钮不归浮层管，按压放大、指尖发光、按钮颜色融进面板、按住直接滑选全都会丢，和选择列表的手感差一截。锚点确实不是按钮时才用 `MochiPopoverBox`。
- **选项的按下高亮由它所在的容器画**：列表行（`MochiListRow`）只放在 `MochiListCard` / `MochiListSection` 里，高亮连同首末行的同心留白一起盖住；菜单、弹出面板里的选项用菜单引擎的高亮块（离面板内边、和面板圆角同心）。不要把 `MochiListRow` 摆进弹出面板，也不要在行外面再包一层放勾选圈之类的东西（高亮只盖住里面那一截）：行首附加的控件放进行内（`MochiSelectableRow` 的勾选圈就是行的一部分）。同一个触发区只有一套按下反馈，行尾已经是按钮（胶囊）时，行本身不再画高亮。
- **自绘圆角块一律用 G2**：Canvas / drawBehind 里画的高亮块、指示点、进度条、选中胶囊都用 `drawG2RoundRect`（连续曲率），不用 `drawRoundRect`（圆弧圆角，和周围的 G2 形状放在一起一眼就看得出不平滑）。
- **面板正文对齐头部按钮**：`MochiSheetHeader` 不带下边距，正文用 `MochiSheetContent` 包起来，左右边、和头部的距离都取头部按钮的同心内缩。
- **浮在键盘上的工具栏不加底色**：只留按钮本身，按钮用细描边（`colors.outline`）分清边界。
- **有来源按钮的确认从按钮弹出**：操作确认有触发它的按钮时，用 [`MochiConfirmationDialogBox`](../components/popover.md) 从按钮弹出（iOS 26），点外面就是取消、不显示取消项；没有来源按钮时用 iOS 26 的居中确认对话框（`MochiConfirmationDialog`，就是 `MochiDialog`），不再做从底部滑上来的操作列表。弹出层和下拉菜单共用同一套形变（`computeFrame`），不另写一套开合动画。提示气泡（`MochiTipPopover`）也是按钮触发的，同样走菜单引擎。
- **融色引擎的按钮色必须不透明**：打开时真按钮隐藏、浮层里画克隆，下面垫着面板阴影。半透明的按钮色会让阴影透出来，变成一块突然浮起、收起时又瞬间消失的半透明遮罩。卡片里的灰色胶囊先合成到卡片底色上（`MochiDefaults.fill().compositeOver(MochiDefaults.groupedContainer())`）；引擎对没合成的半透明色兜底合成到面板色上。
- **同一条边只留一层抗锯齿**：两个形状边缘重合时（色块下面的棋盘格、底色上的描边），底下那层要内缩或裁进上层形状里，否则底层的半透明边会从上层边缘透出来，形成一圈毛边。只在需要时画底层（不透明的颜色不画棋盘格）。
- **尺寸只有一套动画、不裁正在变化的内容**：内容自己会动画宽高时（计数器文字、模糊替换），外面不再套 `animateContentSize`：两套尺寸动画互相打架，而且 `animateContentSize` 会把正在变宽的内容裁掉一截。角标这类贴着锚点的元素钉住靠近锚点的那条边，只往外长。
- **纯色到透明的渐隐用 smoothstep**：滚动边缘、底部工具栏后面、渐变遮罩都用 `MochiSmoothGradient`（16 段色标逼近 S 曲线），不用两三个色标的线性渐变。渐变遮罩裁掉内容的那条边必须遮满，深浅不能按「还能滚多远 ÷ 渐隐长度」成比例：内容只多出半行时会只遮一半，裁切线清清楚楚。
- **Lazy 列表的刷新要钉住顶部**：Lazy 列表按 key 记住第一个可见项，刷新插到最前面的内容会留在视口上面。`rememberMochiRefreshState` 传 `listState`，刷新结束时还在顶上就钉住第 0 项。
- **系统栏不要强制底色**：Activity 用 `mochiEnableEdgeToEdge()`（不要只调 `enableEdgeToEdge()`），状态栏、导航栏完全透明、关掉系统的对比度遮罩，导航栏和键盘背后不出现一条强制的半透明底。
- **先排版、再动画**：新内容进组合后才开始的进场动画（页面打开、侧推、标签切换、面板弹出、对话框）先等它组合、排版、画完、帧率回稳（至少 2 帧，之后有一帧在 1.5 个刷新周期内画完就开始，最多多等 160ms），等待期间画面停在起点。不能让排版和动画的开头挤在同一帧里：弹簧时钟照走，第一次打开时会从起点一下跳到半路。被盖住的页面内容单独一层，重新露出来时不整页重录。
- **浮在内容上的栏要登记遮挡物**：顶栏、底栏、工具栏、滚动边缘渐隐用 `mochiNavOccluder`（库里的栏已自带）。卡片从栏下面打开成页面时，栏先留在变形的容器上面、随打开进度淡掉，缩回时原路淡回，起点和落地都和点之前一样；不能让容器一出发就把栏一下盖住。

详见 [通用效果](effects.md)、[越界回弹](overscroll.md)、[导航](navigation.md)。

## 七、按压和光

- 按下立刻有反馈：从指尖亮起的柔光、轻微放大或形变（`mochiPressGlow` / `mochiPressDeform`）。不给按下的元素描亮边。
- **滚动优先于按压**：在滚动容器里（列表、网格里的卡片和行），按压反馈先等一小会儿（90ms）、手指没动才开始，只是想滚动时卡片不闪；滚动一接手就收回，不能一边滚一边保持按下；快速轻点也补一次完整的按下和回弹，和点击触发的转场同时进行。按压形变和按压高光共用同一套触摸节奏（`awaitMochiPress`），总是同时开始、同时结束；库里新增按压效果也走它，不要各自 `awaitFirstDown` 一套；应用里直接用 `mochiPressGlow` / `mochiPressDeform` 就有这套节奏。
- 光从手指处亮起、平滑地暗下去，不能是一块白斑。
- HDR 光（实验性）：在线性光里只放大颜色的彩色部分，各层之间不相加，也不往白色混；大面积的光保持 SDR。详见 [HDR 高光](hdr.md)。

## 八、触感

少而准：只在状态真的变了，或者「现在松手会发生什么」变了时才震。轻点和松手默认不震。只用组合原语，不用 `vibrate(ms)`。详见 [触感](haptics.md)。

## 九、复用

- 需要菜单就用 `MochiDropdown` / `MochiIconDropdown` / `MochiContextMenu`，需要按钮就用 `MochiButton` / `MochiBarIconButton`。不要抽出一部分自己重画，那样会少掉一半效果。
- 通用效果不够用时，扩展 `effect/` 模块（保持向后兼容），不要在组件里另写一份。
